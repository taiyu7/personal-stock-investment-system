# 系統架構

## 分層說明

### 1. AI Orchestrator

負責協調不同 AI client 的工作。未來可以處理：

- 任務分派
- 分析流程編排
- 多模型結果比較
- 記錄分析結論與決策理由

### 2. AI Clients

放置不同 AI 平台的使用方式與提示詞模板：

- `clients/chatgpt/`
- `clients/claude/`
- `clients/gemini/`

這一層不直接碰資料庫，原則上透過 MCP 取得工具能力。

### 3. MCP

MCP 是 AI 與本機股票系統之間的標準工具介面。第一版建議先做唯讀，不碰下單。

未來可提供：

- 查詢股票基本資料
- 查詢歷史行情
- 查詢市場廣度
- 查詢產業強弱
- 執行回測
- 讀取交易紀錄

MCP 不直接存取 Streamlit 或 yfinance。它會透過共用的市場資料服務與個人紀錄 repository 查詢資料。

### 4. 股票 DB

保存結構化資料，例如：

- 股票清單
- 日線 / 分線資料
- 財報資料
- 交易紀錄
- 持倉快照
- 策略訊號

### 5. 市場資料

負責外部資料擷取、清理、轉換與匯入。第一版使用 yfinance 按需抓取觀察清單與回測標的，不建立全台股常駐資料庫。

### 6. Dashboard

`apps/dashboard/` 是每天使用的盤前與盤後工作台。它只負責畫面與互動；行情、訊號與每日復盤儲存都由共用核心套件處理。

### 7. 回測

負責策略定義、歷史模擬、績效統計與報告輸出。

## 初期設計原則

- 先唯讀，再寫入。
- 先資料可信，再策略複雜。
- 先本機可重現，再自動化。
- 先記錄決策理由，再考慮交易執行。
